# 国标麻将对局引擎（GX-2 · server/internal/engine）

**状态** 交付稿 · 2026-10-17
**范围** 一局国标麻将的完整纯逻辑对局引擎：发牌、摸打、吃碰杠、胡牌/流局判定，全流程可驱动、可验证。
**规则依据** 《中国麻将竞赛规则》（国标 98）与 WMO《麻将竞赛规则》，歧义点裁定见下文与 [docs/engine-rules.md](engine-rules.md)（含来源）。
**不在范围** 番种计分与 8 分起和线（GX-3）；网络、房间、进程组装与客户端界面（GX-4 及后续联机）。
**口径说明** 引擎按 **136 张（无花牌）** 实现——这是**项目级简化裁定，不是国标原文**（98/WMO 均为 144 张含 8 张花牌），见 §6.10 与 engine-rules.md §1.1。

---

## 1. 引擎形状（依 GX-1 选型报告 §5.2）

- **纯逻辑、零网络/界面依赖**：只依赖 Go 标准库（`fmt`、`math/rand`）。
- **状态只在包内**：完整对局状态是 `Game` 的私有字段；对外只有三条通道——
  - `Apply(seat, Action) ([]Event, error)`：上层提交动作意图，引擎校验座位、时机、合法性，合法则推进并回事件，非法则拒绝且**状态不变**；
  - `Actions(seat) []Action`：该座位当前全部合法动作（驱动 UI 与模拟）；
  - `ViewFor(seat) Snapshot`：按座位出快照，**快照的 JSON 形状即协议载荷**。
- **隐藏信息由类型收口**：任何快照不含他人手牌；**他人暗杠的牌面也不出快照**（只留副子种类与出处）；终局后 `Result` 全揭示（国标终局翻牌核对）。
- **服务器权威结构**：上层（本地原型的本机服务端 / 联机权威服务端）只是"与引擎分离的调用方"——把客户端 `action` 翻译成 `Apply`，把 `Event` 翻译成回执/广播，按座位分发 `ViewFor`。`EvDrawn` 的牌面只应发给摸牌者本人。

## 2. API 一览

| 入口 | 说明 |
|---|---|
| `NewGame(seed, dealer) *Game` | 洗牌、四家发 13 张、庄家先摸成 14，进入庄家打牌阶段。同种子对局完全确定（复现/回放）。 |
| `Game.Apply(seat, Action)` | 唯一推进入口。动作：打牌、吃、碰、明杠、暗杠、补杠、和（自摸/声明）、过。 |
| `Game.Actions(seat)` | 当前合法动作清单（含吃的各种组合）。空＝该座此刻无可动作。 |
| `Game.ViewFor(seat)` | 座位快照：手牌、全桌副子（他人暗杠抹面）、牌河、牌墙余数、阶段、窗口信息、终局结果。 |
| `Game.Phase()/Turn()/Over()/Result()/Log()` | 阶段（打牌/声明/终局）、行动座位、终局判定、结果、完整事件日志。 |
| `Decompose(tiles, melds) []WinHand` | （导出）枚举 14-3×副子 张暗牌的全部合法和牌分解——GX-3 计分的直接输入。 |

## 3. 一局的状态机

```
PhaseDiscard（行动者手 14 形态：可打牌 / 暗杠 / 补杠 / 报自摸）
   │ 打出一张 ──────────────► PhaseClaim（声明窗口，牌在牌河中公开展示）
   │ 暗杠 ── 牌尾补牌 ──► 仍是 PhaseDiscard（可连杠）        │
   │ 补杠 ──► PhaseClaim（抢杠窗口：只可和/过）               │
   │ 报自摸 ──► 终局（和牌）                                  ▼
   │                                        全部声明收齐 → 按优先级结算：
   └── 声明优先级：和（截和/头跳）＞ 碰/明杠 ＞ 吃 ＞ 无声明
            无声明 → 下家从牌头摸牌 → PhaseDiscard；牌墙空 → 流局终局
```

要点：

- **声明窗口**：打出/补杠后，其余三家各自声明（吃/碰/明杠/和/过）。引擎在**声明校验时**即拒绝非法声明（不成顺子的吃、无对子的碰、不成和牌的和等），窗口收齐后按优先级一次性结算。
- **自动收束（确定性优化）**：若三家对这张牌既无和也无碰杠吃的可能，引擎直接结算推进（少一轮往返）。这不改变结果：无可行声明者本来只能过。GX-4 的 table 层可无视此优化按超时补"过"。
- **截和（头跳）**：多家报和取离供牌者最近者（下家 → 对家 → 上家），一盘只一人和牌。
- **吃仅上家**：只有供牌者的下家可吃；同一张牌碰/杠与吃冲突时碰/杠优先。
- **杠**：明杠（别人打出＋手中三张）、暗杠（手中四张）、补杠（碰后加第四张）。三种杠都从**牌墙尾部**补牌；**牌墙无牌可补时不得开杠**（口径见 §6.7）。补杠先开抢杠窗口：被抢则刻子保持碰、牌归和牌者；无人抢则升杠并补牌。
- **同巡不报杠（WMO 3.6.8）**：吃、碰的同一巡内不得开杠（暗杠/补杠都不可），再拿牌（摸牌或杠后补牌）后才能开杠；连杠不受限（每次杠都有补牌）。
- **流局**：国标不保留王牌，牌墙抓完仍无人和牌即流局（荒庄）。牌墙摸尽后的碰/吃仍可发生，之后的和牌按海底捞月上下文记录。
- **终局**：和牌（自摸/点和/抢杠和）或流局。`Result` 记录胜者、胡牌张、方式、放铳/被抢座位、**全部和牌分解**（计分取最优）、各家终局暗牌与副子、计番上下文。
- **输入防线**：座位越界、非法牌值、未知动作种类一律拒绝且不改状态，任何输入不引发 panic；吃声明严格校验三张同花色数牌连续（跨花色/字牌拼"顺"被拒）；快照/事件/终局结果与引擎状态深拷贝隔离，调用方改动输出不污染引擎。

## 4. 和牌判定（结构＋时机）

引擎枚举暗牌（含胡牌张）的全部合法分解，五种和牌牌型：

| 牌型 | 构成 | 备注 |
|---|---|---|
| 标准型 | 4 副顺子/刻子（吃碰杠副子各充当 1 副）＋1 对将 | 基础牌型（WMO 3.7.2） |
| 组合龙型 | 组合龙（三花色 147/258/369 不能错位，计 3 副特殊顺子）＋1 副面子＋将 | 至多配 1 副吃碰杠副子（张数所限）；WMO 35「特殊顺子」＋2006 问答通行裁定 |
| 七对 | 7 个对子（须门清） | 4 张同值可当两对（98 牌例＋盛琦 Q56 口径） |
| 全不靠 | 14 张单张：数牌按三花色 147/258/369 不错位排列＋字牌单张（须门清） | WMO 34；满 7 字牌为七星不靠（GX-3 判） |
| 十三幺 | 13 种幺九字牌各一＋恰一种成对（须门清） | WMO 3.7.2 特殊牌型明文 |

和牌时机三入口全部覆盖：**自摸**（含开局第一张、杠后补牌＝杠上开花、牌墙最后一张＝妙手回春）、**点和**（牌墙空时的牌＝海底捞月上下文）、**抢杠和**。8 分起和线**不在引擎内**：引擎只给出结构判定与全部分解，门槛判定归 GX-3。

`WinContext`（随 `Result`）为 GX-3 记录事实：庄家、杠上开花、妙手回春、海底捞月、庄家开局第一张自摸（Initial）、头一轮（无吃碰杠且各家至多打过一张）、打牌数、副子数。引擎只记事实，不定番种名；注意**国标 81 番种没有天和、地和**（98 出版前已删除）——Initial/FirstGoAround 只是事实记录，不是番种判定输入。

## 5. 与 GX-3 / GX-4 的接口

- **GX-3（番种计分）**：`Result.Decompositions`（全部合法分解，计分取最优）、`Result.WinnerHand/WinnerMelds`（明杠/暗杠/补杠出处齐全，门清与刻子明暗可判）、`Result.Context`（上述事实）。座位风＝庄家为东、下家南、西、北；圈风是跨局概念，由上层随局传入（GX-4+）。
- **GX-4（本地原型）**：动作流按 GX-1 报告 §5.2 组装——客户端 `action` → table 层 → `Apply` → `Event` 回执/广播（`EvDiscarded`/`EvDrawn`/`EvMeld`/`EvWin`/`EvExhaustive`）；`Snapshot` 的 JSON 即 S→C 载荷；`Actions(seat)` 驱动可点按钮；`EvDrawn.Tile` 只发给摸牌者。
- 协议类型源头约定（tygo 生成 TS）落到 `server/internal/protocol`（GX-4 建立时），引擎导出类型的 JSON 标签已按载荷形状命名。

## 6. 规则歧义点裁定记录

细节与来源见 [docs/engine-rules.md](engine-rules.md)。本引擎的落点：

1. **一炮多响**：采截和制（头跳）——多家报和取供牌者下家方向最近者，一局一胜者。
2. **流局条件**：国标不保留王牌，牌墙（含杠补牌）抓尽无人和牌即流局。
3. **杠后补牌**：从牌墙尾部抓；牌墙空时不得开杠/补杠（无补牌则手数不守恒）。
4. **抢杠**：仅限补杠（加杠）声明时的窗口；明杠（直杠）不存在抢杠（弃牌窗口本已覆盖和牌优先）。
5. **七对四同值**：允许当两对（番种列表示例「另计七对，四归一」口径）。
6. **组合龙配副**：组合龙＋1 副面子＋将成立（2006 问答通行裁定），至多 1 副吃碰杠副子。
7. **海底捞月口径**：和牌时牌墙已空（终局阶段的打出牌），含碰吃链条后的打出。
8. **吃碰杠后**：碰/吃后立即打牌（不摸牌）；杠后补牌再打牌；杠后可连杠（见 11），吃/碰后须再拿牌方可开杠。
9. **天和/地和不存在**：国标 81 番种无天和、地和（98 出版前删除，见 engine-rules.md §8.2）。庄家开局第一张成和按普通和牌处理（自摸类）；引擎仍记录 Initial/FirstGoAround 事实供核查。
10. **136 张口径（项目级简化裁定）**：国标原文为 144 张（136 序数牌＋8 张花牌）。本项目按 136 张实现：无补花流程与花牌计分，荒牌阈值随之为第 136 张。此为对官方规则的**已知偏差**（后果与对齐路径见 engine-rules.md §1.1），是否对齐 144 张由 Assignee 决定。
11. **同巡不报杠**（WMO 3.6.8 明文）：吃、碰的同一巡内不得开杠，再拿牌后方可；连杠不受限。
12. **牌墙摸尽时的杠**：引擎口径＝无牌可补则报杠不成立、须照常打牌（WMO 3.6.8 规定报杠后必须立即补牌；盛琦 §5.3 的「杠照开而免补牌」口径会破坏 13 张形态，不采——两种读法都满足「有进必有出」）。
13. **庄家第 14 张**：发牌所得非自摸摸牌，但成和按自摸类处理（engine-rules.md §8.2 裁定）；引擎以 DrawInitial 区分来源。

## 7. 验证

- **单元测试**（`engine_test.go`、`win_test.go`、`zz_orch*_probe_test.go`）：发牌与庄家先摸、暗杠牌面视图抹除（可见性守恒：任一座位可见＋隐藏＝136）、非法动作逐一拒绝（非本座/手中无牌/非上家吃/不成顺子/碰对不足/报和无牌型等）、吃仅上家、和＞碰＞吃优先级、截和顺序、杠后牌尾补牌（牌头牌尾区分验证）、明杠/补杠/抢杠全路径、流局、庄家开局自摸、自摸分解、确定性（同种子两跑事件日志一致）、五种和牌牌型分解与 melds=0..4 组合、同巡不报杠、输入防线（越界座位/非法牌值/跨花色与字牌假吃/快照深拷贝隔离——由外部对抗性探测补强为回归测试）。
- **大规模随机模拟**（`simulate_test.go`）：8000 局 × 两种策略（高声明率 0.9 / 低声明率 0.2），每步校验不变式——136 张牌守恒、每牌值 ≤4、手牌形态（14/13 形态随阶段）、牌值全程合法、对局必然终局（实测单局 ≤120 步）。终局校验和牌分解可由胜者手牌重构。
- 实测覆盖（含路径统计）：和牌 938（自摸 199 / 点和 739 / 抢杠和 0——抢杠路径由单元测试定点覆盖）、流局 7062、吃 31350、碰 22657、明杠 576、暗杠 297、补杠 1020、杠上开花 3、妙手回春 5、海底捞月 22、随机局出现组合龙和 1（十三幺/七对/全不靠由单元测试定点覆盖）。
- 复现：

```bash
cd server
gofmt -l .        # 应无输出
go vet ./...      # 应无输出
go test ./... -count=1              # 全部通过（模拟约 4 秒）
go test ./internal/engine/ -run TestFullGameLog -v   # 一局完整对局日志样例
```
